# Phase 0 — Audio Spike (Design)

Date: 2026-06-24
Project: Focus Noise Sculptor (iOS)
Status: design — awaiting approval

## Goal (the gate)

Answer one question before any product UI is built:

> Does synthesized white noise routed through an 8-band EQ sound **clean and pleasant on headphones**, and do **white / pink / brown** emerge convincingly by tilting the bands?

If yes → proceed to Phase 1 (build the designed Sculpt screen).
If no → rethink the synthesis approach before investing in UI. This is throwaway code; correctness of *sound*, not polish, is the deliverable.

## Scope

In:
- AVAudioEngine graph generating white noise in real time.
- 8-band parametric EQ (`60 / 125 / 250 / 500 / 1k / 2k / 4k / 8k`).
- Minimal SwiftUI screen: 8 vertical band sliders, White/Pink/Brown buttons, big Play/Pause.
- Project generated by **Tuist** with a modular skeleton (AudioEngine module + App target).
- Runs on the iOS simulator (path/no-crash check) and on a real device (the actual quality judgement).

Out (deferred to Phase 1+):
- Preset persistence, iCloud, animation engine, stereo-width UI, background mode,
  interruption/route handling, the Dock visual design system, focus-session layer.

## Architecture

Tuist workspace with a clean module boundary that mirrors the product's "layer model":

```
Sculptor (workspace)
├── AudioEngine        (framework) — the defensible core, no UI imports
│   ├── NoiseGenerator
│   └── NoiseEngine
└── Sculptor (App)     — SpikeView + app entry, depends on AudioEngine
```

DesignSystem module is intentionally NOT created in Phase 0 (no design needed yet);
it arrives in Phase 1.

### Units

1. **`NoiseGenerator`** (AudioEngine module)
   - Wraps an `AVAudioSourceNode`.
   - Render callback fills the output buffer with white noise.
   - **Real-time-thread discipline:** no locks, no heap allocation, no Swift ARC traffic
     inside the callback. Uses an inline fast PRNG (xorshift128+ or similar) seeded per channel.
   - White noise = sum of a few uniform randoms (central-limit → smoother, less "digital fizz"
     than a single uniform sample), scaled low (~0.15) to leave clipping headroom.
   - Separate decorrelated L/R streams (independent PRNG state per channel) so stereo-width
     can drop in later without reworking the generator.

2. **`NoiseEngine`** (AudioEngine module)
   - Owns `AVAudioEngine`. Graph: `sourceNode → AVAudioUnitEQ(8 bands) → mainMixerNode → output`.
   - Configures `AVAudioSession` category `.playback`, activates on start.
   - Public API:
     - `start()` / `stop()`
     - `setGain(band: Int, dB: Float)`
     - `apply(preset: NoisePreset)` where preset is a `[Float]` of 8 band gains
   - Band gains are read by the EQ (AVAudioUnitEQ is engine-managed; setting `globalGain`/band
     `gain` is thread-safe via the audio unit), so the UI never touches the render callback directly.

3. **`SpikeView`** (App target)
   - 8 vertical `Slider`s, range −24…+12 dB, each bound to one EQ band.
   - Three buttons: White (all 0 dB), Pink (≈ −3 dB/octave tilt), Brown (≈ −6 dB/octave tilt),
     applied as 8-value gain arrays.
   - One large Play/Pause button toggling `NoiseEngine.start()/stop()`.
   - Plain system styling — NO Dock design system in Phase 0.

## Color shaping (white / pink / brown)

Implemented as **EQ tilt presets** over the white-noise source:
- White: all bands 0 dB (flat).
- Pink: ≈ −3 dB per octave across the 8 bands.
- Brown: ≈ −6 dB per octave across the 8 bands.

Honest caveat: EQ-tilting white noise *approximates* true pink/brown (which use dedicated
filters). But EQ-tilt is the product's actual sculpting mechanism, so validating it here is
exactly the point — not a shortcut.

## Data flow

```
UI slider / preset button
   → NoiseEngine.setGain / apply(preset)
      → AVAudioUnitEQ band gain (audio-unit thread-safe)
NoiseGenerator render callback (RT thread)
   → fills buffer with white noise → EQ shapes it → mixer → output
```

UI and the render thread never share mutable state directly; shaping happens entirely
through the EQ audio unit's own parameters.

## Error handling

- `AVAudioSession` configuration/activation wrapped in `do/catch`; on failure surface a
  simple on-screen message (spike-grade, not productized).
- Engine `start()` throws are caught and reported to the view via a published error string.
- No interruption/route-change handling in Phase 0 (deferred — Phase 1).

## Testing / validation

- **Build:** `tuist generate` then `xcodebuild` build succeeds for the iOS simulator.
- **Smoke run:** launch on booted `iPhone 17 Pro` simulator — engine starts, no crash,
  sliders move band gains, preset buttons change the timbre.
- **The real gate (manual, by the user):** run on a real device with headphones and judge
  sound quality. Simulator audio fidelity is NOT trustworthy for this judgement.
- Light unit test in AudioEngine module: `NoiseGenerator` produces non-zero, bounded samples
  and Pink/Brown preset arrays are monotonically decreasing tilts.

## Tooling

- **Tuist 4.200.5** for project generation (`Project.swift` / `Workspace.swift` manifests).
- Xcode 26.5, Swift 6.3, iOS target.
- Verify Tuist supports Xcode 26.5 during setup; if generation breaks, fall back to a
  hand-written minimal project for Phase 0 and revisit Tuist at Phase 1.

## Definition of done

- `tuist generate` produces a buildable workspace with AudioEngine + App.
- App runs on the simulator without crashing; sliders and White/Pink/Brown work audibly.
- User has listened on a real device and made the go/no-go call on sound quality.
